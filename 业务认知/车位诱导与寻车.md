# 车位诱导与寻车

> 所属：HCP > 停车场 > 停车诱导配置 / 停车场地图；设备 > 诱导管理器 / 显示屏 / 车牌识别相机 / 自助查询设备；寻车客户端
> 版本演进与具体需求见 `版本迭代/`；本文只讲**不随版本变的业务概念**。（配置链路以 v3.1.5 真实环境为准，源图见 `原始素材/实况截图_v3.1.5/停车诱导配置/`）

---

## 一句话定位
解决车主在场内的两个焦虑：**进场找不到空位**、**回来找不到车**。前者靠车位诱导，后者靠反向寻车。二者共用同一套"设备 + 车位状态 + 场内地图"底座——**先把这套底座配起来（配置链路），运行时才能引导车主（应用链路）**。

---

## 核心概念一：先有"配置链路"，才有"应用链路"
理解本模块的关键是分清两条链路——大多数人只看到应用，其实一切始于配置。

**① 配置链路（管理员搭底座）**：以"停车场 > 楼层"为单位，四步向导把设备、地图、车位、位置对应起来：
```
关联设备 → 配置地图 → 配置车位类型 → 标记设备
```
- **关联设备**：把这层楼要用的设备挂到楼层（四类，见概念二）。
- **配置地图**：给楼层配一张车位地图。**只有矢量地图（.map）能识别/标定车位**；静态图（jpg/png）只是底图，会提示"该地图格式下不支持匹配车位"。
- **配置车位类型**：在地图上圈选车位、赋予**车位类型**及对应的车辆停放规则（见概念三）。
- **标记设备**：把显示屏、自助查询设备等的**物理位置**标到地图上，让监控与寻车知道它们在哪。自助查询设备还要配**朝向**（四个方向之一）——因为寻车终端给出的是"往左/往前"这类相对指引，设备朝哪边站着，决定了指引对不对。
- 地图上还可配**是否显示车位号**（默认显示，可一次应用到该场所有楼层）——车位密集时编号会让图面难读。

**② 应用链路（运行时引导车主）**：
```
车位检测（地磁/视频）→ 平台聚合余位（按楼层/分区/类型）→ 诱导屏/车位屏显示空位与方向 → 车主按指引停
```

> 心智模型：**配置链路是"把现实世界登记进系统"，应用链路是"系统把信息推回现实世界"。** 前者一次性搭好，后者持续运转。

## 核心概念二：可绑定的设备及其能力
诱导不是单一设备，而是一套分工协作的硬件，配置时按楼层关联：

| 设备类型 | 角色 | 提供的能力 |
|---|---|---|
| **诱导管理器**（TPM 主机，如 DS-TPM400） | 诱导系统的"大脑" | 汇聚下挂的车位检测器与指示灯，判定并上报每个车位空/占，驱动诱导逻辑 |
| **车牌识别相机**（ANPR / 视频车位相机） | 视频检测端 | 一机多位地视频检测车位占用，兼做车牌识别 |
| **显示屏**（LED） | 信息输出端 | 三类：**入口显示屏**（出入口过车信息，见 `停车场与车道.md`）/ **入口引导屏**（整场余位）/ **停车诱导屏**（场内分方向余位，含室内与室外）；另有车位屏做单车位红绿指示 |
| **自助查询设备**（寻车终端） | 面向车主的查询端 | 车主自助反向寻车（见概念五） |

补充：**地磁设备**是另一种单车位检测器（每车位一个），与视频检测互为选择——都是给"大脑"喂车位空占状态的检测手段。

> 要点：**放行判断/诱导能选什么，取决于这层楼关联了哪些设备。** 没关联视频相机就没有视频车位检测，没关联显示屏就无处显示余位。

## 核心概念三：车位类型——系统给一批默认，用户可再自定义
系统**预置多种车位类型**（普通 / 允许停放 / 禁止停放 / 充电 / 专用，部分版本还有 VIP），用户可在此基础上**自行增删、新增自定义类型**——不是只能用系统写死的那几种。
- 每个车位类型 = **名称** + **标记颜色**（系统色板 / 取色器 / HEX）+ **颜色同步至设备**开关。
- 配置时把地图上的车位圈选后赋予某个类型，并配**停放规则与余位统计**（哪些车允许/禁止停、是否统计余位；除专用车位外默认开启余位统计）。这样把"车的身份"和"车位的类型"对应起来。
- **颜色同步至设备**：车位类型的颜色可下发到诱导指示灯/屏，让现场灯色与平台一致。但**只有系统色板里的预置色能同步**——用取色器/HEX 调出来的自定义色，同步开关会置灰并提示不支持。原因很实在：指示灯只能发出固定几种颜色，平台可以显示一千六百万色，设备不能。
- 推论：**要"平台与现场灯色一致"，就只能在系统色板里选**；选了自定义色，等于接受"平台上好看、现场灯不认"。

推论：余位必须**按类型分别统计**（VIP 满了不代表普通满）；地图和屏上的颜色语义，都来自这套（默认 + 自定义）车位类型。

## 核心概念四：车位有 5 种状态，是诱导与监控的实时依据
每个车位随时处于以下之一（源自 2.4 基线）：
| 状态 | 含义 |
|---|---|
| **空闲** | 无车停入 |
| **占用** | 有车停入 |
| **停车超时** | 停入时长超过该场（或该车辆名单）配置的最大允许停放时长 |
| **非法停车** | 车不在该车位的允许停放列表内，或停进了禁止停放车位（与超时并存时按非法停车展示） |
| **未知** | 该车位无车位相机对应，或对应相机离线 |
- 状态变化由"车辆停入/离开"事件驱动，也可能因**改停放列表、达到超时、相机离线/上线**等而变。
- 状态实时推送到客户端；**非法停车/停车超时会触发报警**（见 `监控报表与运维.md`）。

## 核心概念五：楼层余位怎么算，取决于关联了什么设备
同一个"空余车位数"，来源不同、算法不同（源自 2.4 基线）：
- **只关联 ANPR 相机**：靠进出过车事件加减——进一辆减 1、出一辆加 1（易累积误差，故有**定时校准**）。
- **只关联诱导管理器**：靠车位相机上报的每个车位占用情况——空余 = 总车位 − 占用车位（更准，逐位统计）。
- **两者都关联**：ANPR 统计楼层进出（供入口引导屏显整层余位），车位相机做楼层内诱导（供室内诱导屏显各方向余位），并可同步车位相机数据校正楼层余位。

> 要点：**"整层余位"和"某方向余位"可能来自不同设备**——理解一个诱导现场，先看它这层关联了 ANPR 还是诱导管理器还是两者。

**另有一个统计口径问题：固定车位是否算作"空余"。** 固定车位已被包期车占用配额，临时车无法停放。余位统计中有一个开关决定**固定车位是否计入空余车位计算**：
- **不计入**：出入口屏与诱导屏显示的空闲车位数排除固定车位，即临时车实际可用的车位数。
- **计入**：屏显为全场物理空位，含临时车无法使用的部分。

对应地，**固定车位是一组独立配额**（总固定车位数 / 空余固定车位数 / 固定车位满是否放行），配置在**固定车放行规则**下，且只对选中车辆名单中的车辆生效——它是放行约束，不是停车场的物理属性。

**此外，一块屏的统计范围未必等于它所在的停车场。** 诱导屏可关联多个停车场/楼层并合并显示余位，用于综合体中多个车场共用一块引导屏的场景。因此判断屏上的数字需确认三件事：**统计哪几个停车场、是否含固定车位、余位为 0 时如何显示**。

## 核心概念六：矢量地图是配置与应用的共同底座
停车场/楼层地图承载"车位在哪、设备在哪、分区是什么颜色"：
- **矢量地图**能标车位、能圈类型、能标设备位置——是配置链路第 2~4 步的画布；**静态图**只能当背景，不支持配车位。
- 它同时服务应用侧：诱导点亮空位、监控点车位看详情/历史、分区着色。
- 因为图上焊着大量车位与设备标记，**换图是高风险操作**——只有矢量换矢量才保留这些配置，否则要重标。
- ⚠ 演进：2.4 白皮书称"仅支持静态图、不支持矢量"，3.1 起已支持矢量地图——以 3.x 为准（见 `00_总览.md` 存疑区）。

## 核心概念七：反向寻车是"车牌 → 停放位置"的逆向查询
诱导是"车找位"，寻车是"人找车"。车主在**自助查询设备**（场内寻车终端）输入车牌，反查停在哪。
- 终端面向公众且落地海外，故强调**品牌化与易用**：LOGO 位置可定制、键盘可适配多语种车牌。
- 寻车依赖的仍是车位状态与过车记录这套底座数据，只是查询方向相反。

## 停车场级的辅助配置
除楼层配置外，停车诱导配置在停车场级还有几项"保持车位数据准确"的设置：配置车位关灯时间、**定时校准车位**（周期性把平台车位状态与现场对齐，纠正累积误差）、允许停留时长、有效期到期提醒。

## 边界与异常

| 场景 | 系统行为 | 出处 |
|---|---|---|
| 楼层用的是静态图（jpg/png） | 不支持匹配/标定车位，提示「该地图格式下不支持匹配车位」。只有矢量图(.map)可以 | v2.4→v3.1 |
| 更换楼层地图 | **只有矢量换矢量才保留**车位与设备标记；换成静态图需全部重标。高风险操作 | v3.1 |
| 车位类型用取色器/HEX 调的自定义色 | 「颜色同步至设备」开关置灰并提示。指示灯只认预置色 | v3.0 |
| 车位无对应相机 / 相机离线 | 车位状态显示为**未知** | v2.4 基线 |
| 车位同时超时且非法停放 | 按**非法停车**展示 | v2.4 基线 |
| 批量选中车位后配置 | 所选车位配置不一致时，控件呈**不确定态** | v2.5 |
| 空余车位数为 0 | 屏显可配：显示 0 / X / FULL / 自定义文本（避免"000"语义不明） | v3.0→v3.1.1 |
| 屏显余位与实际空位对不上 | 先查「固定车位是否计入空余车位计算」；再查该屏是否**跨多个停车场**合并统计 | v3.0 / v2.5 |
| 诱导屏关联父停车场 | 勾选父场则子场全选；子场全选不改变父场 checkbox | v2.5 |
| 寻车终端自定义键盘 | 自定义键 ≤100 个；**必须包含 切换/删除/OK**；每行 ≤10 键；保存时校验 | v3.2 |
| 寻车终端 LOGO 配置 | 仅上传 LOGO 后才可配位置；**下发会覆盖设备已有数据**；保存校验是否在可视区 | v3.2 |
| 专用车位 | 默认不开启余位统计（其余类型默认开启） | v3.1 |

## FAQ
- **诱导要配哪几步？** 楼层向导四步：关联设备 → 配置地图 → 配置车位类型 → 标记设备。
- **诱导管理器是什么？和相机什么关系？** 诱导管理器（TPM 主机）是大脑，下挂检测器与指示灯并上报车位状态；视频相机是另一种检测端。二者按楼层关联。
- **车位类型是系统固定的吗？** 不是。系统预置多种（普通/允许停放/禁止停放/充电/专用等），用户可在「车位类型管理」里自行增删、新增自定义（名称+颜色+停放规则+是否同步设备）。
- **同一层的整层余位和方向余位为什么对不上？** 可能来自不同设备：整层余位常由 ANPR 过车统计，方向余位由车位相机统计，二者算法不同。
- **诱导屏、楼层屏、车位屏区别？** 分别对应"整场余位 / 分方向余位 / 单车位红绿灯"三个粒度。
- **为什么我的地图不能标车位？** 用的是静态图；只有矢量地图（.map）支持匹配/标定车位。
- **换停车场地图会丢配置吗？** 矢量换矢量保留车位/设备标记；换成静态图不保留。
- **定时校准车位有什么用？** 周期性把平台车位状态与现场实际对齐，纠正检测累积误差。
- **屏上的空余车位数和实际空位对不上？** 先看"固定车位是否计入空余车位计算"这个开关——不计入时屏显的是临时车可用位数，天然小于物理空位。
- **自定义颜色为什么不能同步到设备？** 指示灯只支持有限的几种预置色，自定义 HEX 色设备认不了，同步开关会置灰。
- **余位为 0 时屏上显示什么？** 可配：显示 0 / 显示 X / 显示 FULL（后续版本还支持自定义文本），避免"000"语义不明。
- **纯诱导、没有出入口的停车场，能查到场内有哪些车吗？** 能。车场剩余车辆检索支持按停车场/楼层/车位号/车牌/停留时间/车位类型查，点开可看泊车信息与车主车辆信息。
