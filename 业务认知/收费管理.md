# 收费管理

> 所属：HCP > 停车场 > 收费规则 / 中心收费 / 充值管理 / 缴费机 / 收费记录 / 收支统计
> 版本演进与具体需求见 `版本迭代/`；本文只讲**不随版本变的业务概念**。

---

## 一句话定位
管"**一次停车该收多少、怎么收上来、怎么对账**"。规则侧定义算钱逻辑，收款侧把钱收上来，记录侧沉淀用于对账与经营分析。

---

## 核心概念一：整个收费体系挂在"收费模式"这个总开关下
停车场先在 基础配置 > 停车场收费模式配置 里定性：**收费场 / 免费场**。
- **免费场**：只有"放行 + 记录"，没有任何算钱/收钱能力。
- **收费场**：才解锁完整链条——收费规则、充值/包期、中心收费/岗亭收费、班次交接、优惠券、收费小票、缴费机、LED 屏金额显示。

> 记忆点：**免费场管"放不放"，收费场才管"收多少"。** 本文其余概念都以"该场已开启收费"为前提。菜单显隐差异见 `00_总览.md`。

## 核心概念二：算钱 = 规则匹配。一次停车可能命中多条规则
收费规则按车的身份分层配置，一次停车按**时段**去匹配，可能命中不止一条：

| 规则 | 管谁 |
|---|---|
| 临时车收费规则 | 无身份的过路车 |
| 固定车包期规则 | 包期车（未覆盖的时段按临时车补） |
| 名单车收费规则 | 名单车 |
| 减免规则 | 优惠/打折 |
| 异常收费规则 | 异常出场兜底 |
| 额外收费规则 | 停车费之外的附加（代泊、小票补办…） |

**计费心智模型**：
- **一段停车时间可拆成多个时段**，各时段按当时适用的规则算，例如"包期覆盖段不计费 + 未覆盖段按临时车算"。所以金额旁常有"查看明细"，把 `时段 × 规则 × 金额` 摊开。
- **计费顺序：先减免、后加额外费**。实收 = (总停车费 − 优惠) + 额外费用。
- **收费类型**决定按什么维度算钱：不收费 / 按次 / 按单位时长 / 分时段 / 分时 / 日夜分时按次 / 按单位时段。

**用哪条临时/名单车规则，有优先级**（源自 2.4 基线）：属某名单且该名单配了规则 → 用名单车规则；否则看车型是否配了临时车规则 → 用之；否则看"不区分车型的临时规则"；再否则用该场第一条临时车规则；一条都没配则不计费（收 0）。

**包期与减免是两类特殊规则**：
- **包期类型**：包年（默认 365 天）/ 包月（默认 30 天）/ 自定义天数 / 闲时包月（按闲时模板，只在非闲时段计费）。
- **"一个月"有两种计法**：充值时可选**自然月**或**日历月**——同一个起始日，两种口径算出的截止日不同。设此选项是因为按固定天数滚动（30 天）与商业习惯中的"一个月"在跨大小月时不一致。⚠两者的精确定义在设计画板上标注自相矛盾，**尚未澄清**，见 `00_总览.md` 存疑区。

## 核心概念二·补：包期可分段充值，因而存在断档
包期不是一次性买断，**可分多次、分不同停车场充值**。由此产生几点：
- **一辆车在一个停车场可同时存在多段包期**：已过期的、正在生效的、以及已充值但尚未开始的（状态"未生效"）。
- **段与段之间可能有空白**，即**断档**——上一段结束到下一段开始之间，该车在该场无包期，按临时车/名单车规则计费。
- 因此"这辆车的包期有效期"没有单一答案：首尾区间可概括范围，但会掩盖中间空白。将多段压缩为一个区间展示时，必须同时给出断档提示，否则会被理解为整段连续有效。
- ⚠**批量充值是覆盖式的**：批量充值后车辆原有效期失效，新有效期以本次充值时段为准，不是在原有基础上追加。这与单车"续费"的语义不同，需注意区分。
- **减免四方式**：折扣（按百分比）/ 金额减免（减固定额，封顶总费）/ 全免 / 停车时长减免（把入/出时间前后推一段再计费）。减免有有效期，可发"减免券"出场时用。

## 核心概念三：免费额度是"反薅羊毛"的博弈
免费停车时长是常见优待，但会被"短时间频繁进出反复领免费额度"钻空子。因此免费判定支持按**自然日累计当日停车总时长**——只要当日累计超过免费额度，超出部分就收费，堵住重复进出逃票。

## 核心概念四：一户多车——包期车位有限，多出来的车怎么算
一个车主包了有限车位却有多辆车时，超出车位的车如何计费：
- **后进收费**：车位停满后再进的车，视为临时车按临时车规则收。
- **先出收费**：出场时按"先出"结算，只对有效车位对应的停车时段计费。

## 核心概念五：钱从多个"收款口"进来，要能归口对账
同一笔停车费可能通过不同**收费来源 × 收费方式**收上来，记录和报表必须能区分、能归口：
- **收费来源**（谁收的）：岗亭、中心收费、缴费机、车主账户扣费。
- **收费方式**（用什么付）：现金、POS、车主账户余额。
- 收费记录是对账主凭证；收支统计分析则把收入按来源/方式/规则拆开做经营分析。

## 核心概念六：中心收费与岗亭收费——两种收款节奏
收费场有两种收款方式，差别在"先付还是后付"：
- **中心收费**：车主在中心**先付费、后出场**，出场时快速放行，提高通行效率。支持按车牌/刷卡/无牌车检索收费、二次收费、减免、打印小票。付了之后可在场内逗留"缴费后允许停留时长"，超时需补交。
- **岗亭收费**：车辆**出场时**由岗亭人员当场结算放行，客户端自动算出金额，支持减免、异常规则、车辆类型切换、减免券、车牌矫正后重算；可现金或车主账户收款。

## 核心概念七：收款终端各有其"人"和"设备"
- **岗亭（CS 客户端）**：值岗人员的工位。核心是"当班要清楚收了多少、交班要交代清楚"——故有独立的**收费概览**和**交班/结束工作**的强确认（避免误退出丢账）。**班次管理**记录操作员上班/交班/下班：登录进车辆监控页即上班，只有手动下班才产生班次记录，统计其当班收费。
- **缴费机**：无人值守收款设备，关键运维指标是**钱箱**（快满要预警，否则满溢停收），因此纳入设备运维（钱箱状态、收币将满阈值报警）。
- **收费小票**：给车主的凭据，可按停车场定制模板（内容/尺寸/排版）。

## 边界与异常

| 场景 | 系统行为 | 出处 |
|---|---|---|
| 免费场 | 收费规则、中心收费、充值管理、班次、优惠券、小票等菜单整体不出现 | v2.4 基线 |
| 一条临时车规则都没配 | 不计费，收 0 | v2.4 基线 |
| **自然月 / 日历月的精确口径** | ⚠ 画板标注自相矛盾（同为 2020/05/21 起，一处到 06/20、一处到 06/21）。见 `待确认.md` | v2.5 待确认 |
| 包期断档时段 | 该车在该场无包期，按名单车规则计费；名单也未覆盖则按临时车规则 | v2.5 |
| 批量充值 | **不校验欠费**；欠费未处理则岗亭无法自动放行 | v3.1.1 |
| 一次停车命中多条规则 | 按时段拆开分别计费，金额旁提供「查看明细」展开 `时段 × 规则 × 金额` | v3.1.1 |
| 同时有减免和额外费用 | 顺序固定：**先减免、后加额外费**。实收 =(总停车费 − 优惠)+ 额外费用 | v3.2 |
| 「放重复进」开关 | 仅限临时车/名单车规则，且仅限按时长/按时段类收费类型 | v3.2 |
| 缴费机钱箱满 | 停止收币。故设「收币将满阈值」(默认 80%)，**但阈值报警需先在事件报警中配置才生效** | v3.2 |
| 中心收费已付费后场内逗留 | 有「缴费后允许停留时长」，超时需补交 | v2.4 基线 |
| 岗亭查看远端站点 | 隐藏收费概览等本地专属操作 | v3.1.1 CS |
| 岗亭交班 / 结束工作 | 二次确认（原"OK"实为退出客户端，易误点丢账）；打印失败降级 | v3.1.1 CS |

## FAQ
- **为什么有的停车场没有收费规则/中心收费菜单？** 该场是免费模式；收费能力整体挂在收费模式开关下。
- **一次停车怎么会有好几条收费规则？** 停车时段被拆分，各段按适用规则计费（如包期段免费 + 临时段计费），可展开明细看。
- **额外费用和减免谁先算？** 先减免后加额外费。
- **免费时长为什么按自然日累计？** 防止频繁进出反复领免费额度逃票。
- **缴费机为什么要盯钱箱？** 钱箱满会停止收币，故有"收币将满"阈值预警并入运维。
- **一辆车既是名单车又买了包期，收费怎么算？** 不是二选一，而是按**时段**拆开：包期有效期内的时段**免费**（记 0）；超出包期的时段要收费，此时因它也是名单车，按**名单车收费规则**算（名单规则优先于临时车；名单没配才回落临时车）；总费 = 各段合计，可展开明细。注意：放行优先级（名单排在固定车前）决定的是"放行方式"，与计费是两套逻辑；若名单车收费规则配成"不收费"则全免；开了"一户多车"且落入该场景时，改按一户多车逻辑（有效期内免费、有效期外按出入时间计费）。
