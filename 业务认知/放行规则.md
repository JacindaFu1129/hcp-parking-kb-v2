# 放行规则

> 所属：HCP > 停车场 > 停车场管理 > 放行规则；及车道级放行、岗亭客户端放行
> 版本演进与具体需求见 `版本迭代/`；本文只讲**不随版本变的业务概念**。

---

## 一句话定位
决定"一辆车到闸口，**放不放、怎么放、谁来放**"。这是停车场最核心的实时决策，其它模块（身份、收费、设备）最终都汇到这一刻。

---

## 核心概念一：一次放行要连过三关
车到闸口，平台依次判断：
1. **校验（是不是本人本车）**：入场/出场分别可要求 防重复进 / 车卡一致 / 人车一致，防止顶包、跟车。
2. **判断（信谁的识别结果）**：放行判断方式 = **ANPR 抓拍优先** 或 **人脸·卡片优先**——决定以车牌识别还是刷卡/刷脸为准。选人脸·卡片优先必须配了对应设备，否则无从判断。
3. **动作（放行 + 算账）**：抬杆放行，同时按收费/扣款规则结算（如账户自动扣款、收费为 0 是否直接放行）。

> 心智模型：**校验管"是不是"，判断管"信什么"，动作管"放不放、扣不扣"。**

**放行判断方式的本质，是多种识别手段之间取"与"还是取"或"**：
- 平台可能同时有三路识别结果：ANPR 抓拍、刷卡、人脸。判断方式规定的是**任一通过即认证成功（或），还是必须都通过（与）**。
- 现存的两个选项都是"与"，差别在**先验哪一路**：人脸·卡片优先为"人脸或刷卡通过后再比对 ANPR"，ANPR 抓拍优先为"抓拍比对成功后再进行人脸识别或刷卡"。排在前面的即该车道的主识别手段。
- 早期还存在一个"或"的选项（任一条件通过即认证成功），后被取消。原因是"或"使安全水位取决于最弱的一路识别，防顶包、防跟车的校验因此失效。

> 判断方式决定的不是使用哪个设备，而是是否要求双重认证、以及验证顺序。

## 核心概念二：放行方式——自动 vs 人工，是"信任度"的选择
- **自动放行**：平台判定通过即抬杆，无人干预，效率优先。
- **人工/登记放行**：岗亭人员确认后放行，用于异常、无牌、争议场景。
- 二者的边界由风险决定：越可能出错或涉钱的场景越倾向人工。例如**超时停放的车不自动放行**——停太久往往意味着有欠费或异常，交给人工处理。

## 核心概念三：规则是"分层继承"的——停车场定调，车道可覆盖
放行规则不是一处配置，而是一套继承体系：
- **停车场级**定统一基调（校验方式、按车辆身份的放行规则）。
- **车道级**默认"与所属停车场一致"，也可"自定义"覆盖（这条道走什么车、用什么判断方式）。
- 因此同一停车场不同车道可以有不同脾气（如某道只走摩托车、某道禁货车）。

## 核心概念四：放行按"车的身份"分别定规矩，且身份有判定优先级
放行规则按身份拆开配：临时车 / 固定车 / 访客车 / 名单车 放行规则。每类可独立设"自动/手动、时段、取卡放行"等。原因同 `车辆与名单.md`：**身份决定待遇**，放行是待遇的兑现点。

**判定这辆车用哪套规则，有固定优先级**（源自 2.4 基线）：
1. 不在有效期内 → 当**临时车**处理；
2. 是**访客车** → 用访客车规则；
3. 是**名单车**且该名单配了规则 → 用名单车规则；
4. 是**固定车** → 用固定车规则；
5. 否则 → 用临时车规则；
6. 若判为不放行，再看**子库车道**：任一子库车道放行，则主库也放行。

此外还有两类"越过普通规则"的判断：**一户多车**（车主在本场有包期车时，改为按有效车位数/占位判断，不再走上面的放行规则）；**节假日自动/免费放行**（命中则直接放行/免费）。

## 核心概念五：免费场看"规则"，收费场出场看"账"
入场判断在免费场/收费场一致（走上面的校验+规则+一户多车+节假日）。**区别在收费场的出场**：
- 收费场出场时，**综合"计费结果 + 一户多车 + 放行模式"判断，而不再看放行规则**。
- 逻辑：访客车不收费直接放；计费失败不放；固定包期车自动确认收费放行；普通车若收费为 0 看"收费为 0 是否放行"，不为 0 则看是否开账户自动扣款且在限额内——是则扣款放行，否则交人工。

> 心智模型：**进场问"是谁、准不准进"，收费场出场问"账清没清"。**

## ★ 核心概念六：离线放行——平台离线时由设备自主放行

前述判断均以平台在线为前提。平台或网络故障时，靠**离线放行**兜底：**将车辆名单预先下发到车道，平台离线时由设备按规则放行名单内的车辆。**

要点：
- **下发对象是车辆名单，不是单辆车。** 因此离线放行开关位于**名单车辆放行规则**上，只对名单车生效；临时车、访客车在设备侧无可比对的名录，离线时无法判断。
- **前提条件：该车道的「道闸控制单元」必须是抓拍单元。** 离线时只有抓拍机能自行识别车牌、比对名单并控制道闸。若道闸由卡箱/票箱控制，该车道无法配置离线放行（开关置灰）。
- **下发可能部分失败**（设备离线、容量不足等），故下发结果与失败原因需可查。**下发成功不等于配置生效**，这是排查"离线放行不起作用"时首先要确认的环节。

**同一个「名单下发」动作，在不同 License 下用途不同**（见 `车辆与名单.md` 概念六）：具备出入口能力时下发到**车道**，用于**离线放行**；仅有 ANPR 能力时下发到**相机**，用于**黑白名单报警**。后者只产生报警事件，但可联动报警输出驱动道闸，从而在无停车场 License 的情况下实现简易出入口控制。

## 核心概念七：无牌车是一条独立的规则线

平台对无车牌、或车牌无法识别的情况单独设规则：
- **无牌车放行规则**是一种特殊的临时车放行规则，可独立于临时车规则单独设置，**默认入场/出场均为手动放行**——无车牌即无自动判断依据，转人工处理。
- **取卡通行**是无牌车与临时车的凭证替代方案：车道关联出入口控制设备后，可开启"临时车取卡通行""无牌车取卡通行"，以取卡/刷卡/还卡作为进出场的对应凭据。开启后即便识别到车牌也不放行，必须走取卡流程——此时卡是该链路的唯一凭据，混用会导致进出记录无法配对。

## 核心概念八：中心呼叫——识别错了怎么补救
抓拍识别错误导致本该放行的车没放行时，车主可用票箱/可视对讲按钮**呼叫中心**，由中心人工放行。平台会把呼叫事件与该车道"当前未放行记录"合并（每车道只留一条、生命周期约 3 分钟），推给客户端弹窗处理。这是自动识别失效时的人工兜底通道。

## 核心概念九：岗亭是"兜底决策台"
自动放行处理不了的都落到岗亭（CS 客户端）人工处理。岗亭放行的业务重点是**留痕与占位**：
- **登记放行**要能记原因（备注，可设为必填）、能占用名单车位（占了名单的坑要记账）。
- 岗亭还承担收费场的现场收款与放行合一（见 `收费管理.md`）。

## 边界与异常

设计新交互前先过一遍这些已知边界（均已在既往版本中出现）：

| 场景 | 系统行为 | 出处 |
|---|---|---|
| 车道的道闸控制单元不是抓拍单元 | 「离线放行」开关置灰、资源树车道置灰并提示 | v2.5 |
| 选 ANPR 抓拍优先，但车道未配抓拍单元 | 保存报错「当前车道未配置抓拍单元」 | v3.0 |
| 选人脸·卡片优先，但未关联出入口控制/刷卡对讲设备 | 报错，不可保存 | v3.1.1 |
| 停车场未配人车一致 / 车卡一致 | 车道不展示放行判断方式 | v3.1.1 |
| 名单下发部分失败（设备离线、容量不足） | 进度弹窗给出成功/失败数 + 失败详情表（监控点或车道 + 原因）。**下发成功 ≠ 配置生效** | v2.5 |
| 复制节假日放行规则部分失败 | 展开(停车场 / 失败原因)表 + 重试 | v3.1.1 |
| 无牌车 / 车牌识别不出 | 走独立的无牌车规则，默认进出场均手动放行 | v2.4 基线 |
| 已开取卡通行，但车牌识别成功 | 仍不放行，必须走取卡流程（卡是该链路唯一凭据） | v2.4 基线 |
| 超时停放 | 「超时不自动放行」仅在配了"允许停留时长"时出现，且只对"出场自动放行"的车生效 | v3.2 |
| 岗亭登记放行且开了备注必填 | 备注为必填，长度 ≤256 | v3.1.1 CS |
| 车道未开"继承所属停车场规则" | 名单放行规则默认空态 | v2.5 |
| 判为不放行但存在子库车道 | 任一子库车道放行，则主库也放行 | v2.4 基线 |

## FAQ
- **ANPR 优先和人脸/卡片优先怎么选？** 看现场以什么识别为准；选人脸/卡片优先必须先关联出入口控制/刷卡对讲设备。
- **为什么超时的车不给自动放行？** 停太久常伴欠费/异常，转人工更稳妥（且需先配了"允许停留时长"该逻辑才生效）。
- **车道规则和停车场规则冲突以谁为准？** 车道选"自定义"即覆盖停车场；默认则继承。
- **岗亭"登记放行"和"快速放行"区别？** 快速放行直接抬杆；登记放行需记备注/占用名单车位等，用于异常留痕。
- **为什么"离线放行"开关是灰的？** 该车道的道闸控制单元不是抓拍单元。离线时只有抓拍机能自主认车牌并决策，卡箱/票箱控闸的车道配不了。
- **离线放行为什么只有名单车有？** 下发到设备的是"车辆名单"这个整体。临时车、访客车在设备侧没有可比对的名录，离线时无从判断。
- **名单下发成功了，为什么离线还是不放行？** 先分清这套系统属于哪条链路：装了出入口能力时下发到**车道**才是离线放行；只有 ANPR 时下发到**相机**，产生的是黑白名单**报警**而非放行，需另接报警输出才能驱动道闸。
- **开了取卡通行，车牌识别出来了为什么还是不放？** 取卡通行开启后，卡才是该链路唯一凭据，识别到车牌也要走取卡流程，否则进出记录无法配对。
- **无牌车为什么默认手动放行？** 认不出车牌就没有自动判断的依据，默认转人工是唯一稳妥解；它是独立于临时车规则的一条规则线。
