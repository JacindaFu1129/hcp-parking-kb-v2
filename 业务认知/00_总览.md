# 停车场管理 · 总览

> 所属：HikCentral Professional（HCP）> **停车场**
> 本文是分诊节点：给心智模型 + 指路。细节都在别处。

---

## 一句话定位

「停车场管理」把**车牌识别、道闸控制、车位检测**等前端能力，纳入 HCP 的**放行、计费、诱导、记录与报表**体系，实现「车辆进出—识别—计费—放行—统计」的闭环。它是平台从"看得见"走向"管得住、收得起"的关键业务。

---

## ★ 全局总开关与约束

理解任何一个停车场现场，先确认这四件事。它们决定了大量能力的有无：

### ① 收费模式 —— 影响面最大的开关

**基础配置 > 停车场收费模式配置** 决定这个场是「收费场」还是「免费场」，级联控制大量菜单与能力：

| | 免费场 | 收费场 |
|---|---|---|
| 能力 | 只有**放行 + 记录** | 解锁**算钱 + 收钱 + 对账**整条链 |
| 权限来源 | 在人员/车辆的「停车场通行」里**授权** | 通过充值管理**售卖**（详情页只读） |
| 独有菜单 | — | 中心收费、充值管理、班次记录检索、收费小票配置、停车场详情内「收费规则」Tab |
| 屏可插字段 | 空余车位、名单空余车位 | 另有收费金额、账户余额 |

> 口诀：**免费场只管"放行 + 记录"，收费场才有"算钱 + 收钱 + 对账"。**

### ② License 能力 —— 决定走哪条链路

同一个「名单下发」动作，在两种 License 下是两套完全不同的机制：只有 ANPR 时下发到**相机**做黑白名单**报警**；有出入口能力时下发到**车道**做**离线放行**。讨论名单、有效期相关问题前必须先问这一条。详见 `车辆与名单.md` 概念六。

### ③ 平台端 —— BS 还是 CS

- **BS（Web 管理端）**：配置侧。建场、配规则、配设备、查报表。
- **CS（客户端 / 岗亭）**：值守侧。现场放行、现场收款、交班。

同一业务在两端各有一套界面与设计稿，**找稿子必须先确认端**。

### ④ 区域设置 —— 通用还是中东北非

这是个全局开关，会**改变"车牌"这个概念本身的结构**（中东北非下国家/地区转为车牌小字，另有车牌区域、Category）。一旦启用，检索/列表/详情/导出/监控全链路都要适配。

## 通用心智模型：一辆车的一次进出

停车场子主题虽多，主线只有一条：

```
识别 → 放行(入) → 停放与诱导 → 计费 → 缴费与放行(出) → 记录与报表
```

1. **识别**：车牌识别 / 无牌车处理 → 判定这辆车此刻是什么身份
2. **放行（入）**：按规则控闸，记录入场时间与凭证
3. **停放**：车位检测 → 余位统计 → 诱导 / 反向寻车
4. **计费**：出场时按收费规则算钱（免费场跳过）
5. **缴费与放行（出）**：线上/中心/岗亭/缴费机收款 → 抬杆 → 生成出入记录
6. **运营**：流水汇总为报表

> 口诀：**"进"看识别与权限**（是谁的车、能不能进）；**"出"看计费与放行**（该收多少、放不放）。
