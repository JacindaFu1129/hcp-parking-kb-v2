# 车辆与名单

> 所属：HCP > 车辆（车辆信息/车主信息/停车场通行）、人员 > 车辆通行、停车场 > 固定车/名单车、充值管理
> 版本演进与具体需求（谁在哪个版本改了什么）见 `版本迭代/`；本文只讲**不随版本变的业务概念**。

---

## 一句话定位
管"**一辆车是什么身份、归谁、能进哪个场、能进到什么时候**"。车辆管理沉淀车与车主的主数据，停车场通行权限决定它在闸口被如何对待。

---

## 核心概念一：车的五种身份
停车场里的车不是一视同仁，**身份决定收费和放行**。共五类（前四类权益从低到高，末一类是"负向身份"）：

| 身份 | 本质 | 权益 | 收费 |
|---|---|---|---|
| **临时车** | 没有任何登记的过路车 | 进出但无优待 | 按临时车收费规则 |
| **名单车** | 归属某个"车辆名单"（VIP/员工等）的车 | 名单赋予的通行/免费/优待 | 按名单车规则，或免费 |
| **固定车（包期车）** | 买了包期（月租/年租）的车 | 有效期内自由进出其授权车场 | 包期内不计临时费 |
| **访客车** | 访客登记时产生的临时授权车 | 预约时段内可进指定场 | 按访客规则 |
| **黑名单车** | 登记为黑名单、配了禁止通行时段的车 | **禁止通行时段内不放行** | — |

理解要点：
- **身份是"叠加"而非互斥**——一辆车可能既是名单车又关联了人员做了包期；计费时可能命中多条规则（见 `收费管理.md` 的多规则计费）。
- 身份不是车的固定属性，而是"这辆车相对某个停车场此刻的角色"：同一辆车在 A 场是固定车、在 B 场是临时车。
- **登记态区分**：在系统登记过的叫"系统车辆"（免费场关联停车场即成固定车，收费场包期充值后成固定车）；**名单车一定是系统车辆**；**访客车依赖停车场存在**（停车场创建后才有访客名单，访客登记填车牌即入访客名单）。此外"临时卡"按停车场管理，用于临时车发卡/还卡放行。

## 核心概念二：车的主数据 = 车 + 车主 + 凭证
一条车辆记录由三部分构成：
- **车辆本身**：车牌号码、车辆名单、类型、颜色、品牌。海外（SIRA）场景车牌不是一个字段，而是 `国家/地区 + 车牌小字 + 号码 + 大小 + 类型 + 颜色` 的组合（见 `监控报表与运维.md`）。
  - 这些属性不是写死的：平台有一处**车辆属性设置**，用来管**车辆类型**（可增删）、**自定义属性**（数量有限，可作列表筛选项）和**区域设置**。
  - **区域设置是个全局开关**（通用 / 中东北非），它会**改变车牌这个概念本身的结构**：切到中东北非后，原本独立的「国家/地区」字段隐藏，转而作为**车牌小字**参与车牌构成，同时多出「车牌区域」「Category」等维度。⚠**这几个维度彼此独立、不能互相推导**——不要假设选了某国家就能定 Category。
- **车主**：可以是平台里的"人员"，也可以是独立车主。**关联到人员**后，这辆车的权限有效期就跟人员走（见概念四）。车主除姓名外还有**车主 ID** 作为唯一标识（姓名会重名），车辆与名单两侧均可按它检索。
  - 一条硬约束：**只有"从人员模块选择"的车主才能发卡**。独立车主填的只是联系信息，公寓楼等一卡通场景要发卡，必须先把车主落成平台人员——因为卡属于人，不属于车。
- **通行凭证（卡）**：区分**近距 IC 卡**与**远距 UHF 卡**——UHF 卡用远距离读卡器发放、可不停车识别，全平台带「远距离识别」标识以便和普通卡区分。

## 核心概念三：停车场通行权限 = 谁 + 进哪个场 + 什么时段 + 到什么时候
一条权限回答四个问题：**通行车辆**（谁）、**停车场/子停车场**（进哪个）、**通行时段**（每天几点能进）、**有效期**（整体到期日）。

**权限来自哪里，取决于停车场收费与否**（这是最容易踩的坑）：
- **免费场**：权限直接在 人员/车辆 的「停车场通行」里配。可选「控制通行车辆数」——不控制则名下车都能进、不校验车位；控制则限定可同时通行的车辆数。
- **收费场**：**权限是"买"来的**——通过「充值管理」做包期充值获得，人员/车辆详情里只读展示，改权限一律回到充值管理。

> 心智模型：**免费场"授权"，收费场"售卖"。** 同一个"停车场通行"入口，在免费场是配置项，在收费场变成只读凭证。

## ★ 核心概念四：有效期分几种，各自控什么

停车业务里存在多个都叫"有效期"的字段，英文名也接近，容易混淆。区分它们的依据是**各自控制什么**：

| 有效期 | 控制什么 | 说明 |
|---|---|---|
| **停车通行有效期**（通行证 / 停车场通行权限） | 该车能否进入该停车场、到什么时候 | 停车场业务中最关键的有效期 |
| **人员有效期** | 免费场下作为停车通行有效期的默认来源 | 车辆默认与人员一致，也可解耦后单独配置 |
| **名单有效期** | **名单车的放行**，以及名单下发到设备的时间约束 | 见下 |
| **车辆有效期** | **对停车场控制不生效**；用于与设备的车辆名单管理打通 | 历史字段，见下 |

### 停车通行有效期的来源，取决于停车场收费与否
- **免费场**：默认与人员有效期一致，可配置为不一致后单独设置。非人员车无人员可依据，直接在车辆上配置。
- **收费场**：来自通行证，由包期充值获得；人员/车辆详情只读展示，修改需回到充值管理。

> 免费场的通行有效期是**授权**得来的，收费场是**购买**得来的。生效的始终是"停车通行有效期"这一个概念，区别在来源。

### 名单有效期：控名单车放行，同时决定下发给设备的时间
名单有效期与车辆的停车通行有效期是**两个独立字段，服务两类场景**——公司/园区停车场多为免费模式、用名单控制放行；小区业主或商业停车场多为收费模式、用通行证包期。它有两项作用：

1. **控制名单车的放行**：对名单车而言，名单有效期直接决定它此刻是否作为该名单的车被放行；名单放行规则以它为准。
2. **决定下发给设备的时间约束**：名单下发时，下发的有效期取自名单有效期。

计费上的次序是：**先按包期判断，不在包期内的部分按名单车收费规则，两者都不覆盖的部分按临时车收费规则**（见 `收费管理.md`）。

由此得出一条结构性结论：**名单赋予的权限与车辆自身配置的权限并存，不是覆盖关系。** 一辆车可因名单获得 A 场权限，同时自己配置了 B 场权限；名单过期后失去 A 场权限，仍保留 B 场权限。

> ⚠ **存疑（待确认）**：名单有效期**未配置**时，表示永久有效，还是回退为下发车辆有效期。两种处理对纯 ANPR 客户的现场行为影响不同。已登记在 `00_总览.md` 存疑区，正在与 SE 确认。

### 车辆有效期：不控停车场放行，但在纯 ANPR 场景下保留
车辆管理中的"车辆有效期"**对停车场控制不生效**——控制放行的是停车通行有效期。它的实际用途是与设备的车辆名单管理打通：历史上先有 ANPR、后有停车场，纯 ANPR 场景一直使用这个有效期。

因此它的存废按**能力配置与安装来源**分开处理：

| 场景 | 车辆有效期 |
|---|---|
| **旧版本升级、仅有 ANPR License（未购停车场/出入口）** | **保留**，列表与详情正常展示、可修改 |
| 旧版本升级、已开通出入口 | 列表不展示，详情仍可修改 |
| **新安装的平台** | 默认不展示（置为长期有效并隐藏），停车场场景改用停车通行有效期 |

保留的原因：部分客户在无停车场 License 的情况下，用**车辆有效期 + 事件报警联动**实现"系统车匹配 ANPR 后控制道闸"，即以 ANPR 能力搭建的简易出入口控制。删除该字段会直接改变这些现场的放行行为。

### 停车通行有效期不是单个值，而是一组
权限按停车场发放，一辆车在 A 场、B 场各有各的起止；收费场还可分多段续充。因此列表中的「有效期」不是单值字段，而是**按停车场分行的一组区间**，每行带状态：

| 状态 | 含义 |
|---|---|
| **正常** | 当前在有效期内 |
| **N 天后过期** | 临近到期，提醒续费（阈值由停车场的"有效期到期提醒(天)"决定） |
| **已过期** | 区间已过 |
| **未生效** | 充了**未来**的时段，现在还没开始 |

行数多时折叠，展开可看全部。**"未生效"状态说明系统允许充值未来时段**——同一辆车在同一个场可同时存在"已过期的上一段"与"未生效的下一段"，中间的空白即断档。

> 有效期的粒度是"车 × 停车场 × 时段"，不是"车"。把它压缩为单个值展示时，须明确多停车场与断档如何处理。

各类车能否在车辆页修改有效期：
- **名单车**：受所属名单的有效期约束，不在车辆页单独修改。
- **人员车**：默认与人员一致；配置为不一致后可单独设置。
- **非人员车**：无人员可依据，直接在车辆上配置。
- **收费场的车**：来自通行证，车辆页只读，修改需去充值管理。

## ★ 核心概念六：名单下发——名单可下发到前端设备

车辆名单除了是平台内的车辆分组，还可以**下发到前端设备，使设备在脱离平台时自主判断**。

**同一个「名单下发」动作，在两种能力配置下服务两个完全不同的目的**：

| 平台具备的能力 | 下发到哪 | 设备拿它做什么 | 产生的结果 |
|---|---|---|---|
| **只有 ANPR** | 抓拍**相机 / 监控点** | 按名单类型（白名单 / 黑名单）比对车牌 | **报警事件** |
| **有出入口（停车场）** | **车道** | 平台离线时按规则自主判断名单内车辆 | **开闸放行**（见 `放行规则.md` 离线放行） |

要点：
- **纯 ANPR 分支只产生报警，不控制道闸。** 但报警可联动**报警输出**驱动道闸，因此无停车场 License 的客户可用"ANPR + 名单下发 + 报警联动"实现简易出入口控制。这是长期存在且被实际使用的用法，涉及名单或有效期的改动都需先评估对它的影响。
- **下发的时间约束取自名单有效期**（未配置时的处理待确认，见概念四存疑）。在设备离线或纯 ANPR 场景下，设备侧实际依据的就是这个下发值。
- 由此可得：**平台侧生效的有效期与下发到设备的有效期未必一致。** 当一辆车既属于名单、又有停车场通行凭证时，下发给设备的只能是一个值，设备侧与平台侧的判断可能出现差异，该差异只在离线或纯 ANPR 场景暴露。

> 名单在平台侧是车辆分组，在设备侧是一份可离线执行的通行名录。修改名单相关字段会同时影响两侧行为。

## 核心概念七：车、人、名单的归属关系
- 车可**关联车主（人员）**：关联后权限/有效期归**人员模块**管，车辆页只读并提示"前往人员模块"。
- 车可**属于名单**：属于有通行权限的名单时，这条权限"焊死"在车上（不可反勾选/删除），因为它来自名单而非车本身。
- **访客车**是访客登记的副产物：登记访客填车牌即自动生成，预约信息里带它能进的停车场。

## FAQ
- **同一辆车为什么这个场收费那个场免费？** 身份是相对停车场的角色，不是车的固定属性。
- **收费场为什么在车辆/人员详情改不了停车场权限？** 收费场权限是包期"买"的，详情页只读，改权限去「充值管理」。
- **名单车/关联人员的车，有效期怎么改不了？** 有效期继承自名单/人员这些更上位的来源，需到对应源头改；人员车可解耦后单独设。
- **车辆管理里怎么找不到"车辆有效期"了？** 它对停车场放行从来不生效，已被收敛到"停车通行有效期"。只有在**纯 ANPR**（无停车场能力）的场景下它仍然可见可改，因为那条链路上只有它能做时间约束。
- **既然名单有效期也不控放行，为什么不一起删？** 它有两个不可替代的用途：**下发到设备**的时间约束，以及**名单放行规则与名单车收费规则**的判定依据。删了这两处都会塌。
- **名单有效期和车辆通行证有效期是什么关系？** 是**两个独立字段、服务两类场景**（名单常用于免费场控放行，通行证用于收费场包期），不是主从关系。计费上先看包期，包期未覆盖的时段才按名单车规则。
- **怎么区分普通卡和远距离卡？** UHF 远距卡全链路带「远距离识别」标签，普通 IC 卡没有。
- **关联车辆提示"车牌已关联车主"？** 车已有车主，需先解绑才能改关联。
- **车辆名单和"名单下发"是一回事吗？** 不是。名单是平台内的车辆分组；名单下发是把这份名录**推到前端设备**，让设备能离线判断。开不开下发，不影响平台侧的名单权限。
- **为什么改名单有效期要格外谨慎？** 它是**下发到设备的那个判据**。纯 ANPR 客户常把"名单下发 + 黑白名单报警 + 报警输出"当简易出入口控制用，动这个值会直接改变他们现场的开闸行为。
- **车主 ID 是干什么的？** 车主姓名会重名，车主 ID 提供唯一标识，车辆管理与名单管理均可按它检索。
