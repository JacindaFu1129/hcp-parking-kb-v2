# 术语与实体

> 用途：**AI 写界面文案、字段名、说明稿时先查这里对齐命名。**
> 只收**跨两个及以上主题**的实体；只在单一主题里出现的词，就近解释在该主题文件内。

## 实体关系图

```
停车场 ─┬─ 子停车库（不可再嵌套）
        ├─ 出入口 ─── 车道 ─┬─ 抓拍单元（认牌）
        │                   ├─ 出入口控制设备（卡箱/票箱，抬杆）
        │                   ├─ 刷卡对讲设备（≤2）
        │                   ├─ 显示屏
        │                   └─ 关联监控点（≤3，仅辅助，不参与判断）
        ├─ 楼层 ─┬─ 车位 ─── 车位类型
        │        ├─ 诱导管理器 / 地磁 / 视频车位相机
        │        └─ 显示屏 / 自助查询设备
        └─ 规则 ─┬─ 放行规则（按身份分：临时/固定/访客/名单/无牌）
                 └─ 收费规则（临时/包期/名单/减免/异常/额外）

人员 ──关联── 车主 ──拥有── 车辆 ──属于── 车辆名单
                              │
                              ├── 停车场通行权限（车 × 停车场 × 时段）
                              └── 卡片（IC 近距 / UHF 远距）
```

## 一、车的身份（五类）

| 官方叫法 | 也被叫作 | 本质 |
|---|---|---|
| **临时车** | 过路车 | 没有任何登记 |
| **名单车** | — | 归属某个「车辆名单」 |
| **固定车** | **包期车**、月租车 | 买了包期 |
| **访客车** | — | 访客登记的副产物 |
| **黑名单车** | — | 配了禁止通行时段 |

⚠ **「固定车」与「包期车」在产品里混用，指同一类车。** 免费场关联停车场即成固定车；收费场包期充值后成固定车。

⚠ 身份是**相对某个停车场此刻的角色**，不是车的固定属性；且可**叠加**（一辆车可同时是名单车和包期车）。

## 二、★ 四种「有效期」—— 最高频的混淆源

| 官方叫法 | 控制什么 | 别名/俗称 |
|---|---|---|
| **停车通行有效期** | 该车能否进入该场、到什么时候。**停车场业务中真正生效的那个** | 通行证有效期、停车场通行权限有效期 |
| **人员有效期** | 免费场下作为停车通行有效期的默认来源 | — |
| **名单有效期** | 名单车的放行 + **下发给设备的时间约束** | — |
| **车辆有效期** | **对停车场控制不生效**。历史字段，仅纯 ANPR 链路仍用 | — |

写文案时的铁律：**说"这辆车能进到什么时候"，用「停车通行有效期」，不要用「车辆有效期」。** 后者是另一个东西，且新装平台已隐藏。演进过程见 `../版本迭代/演进脉络.md`。

停车通行有效期的粒度是「**车 × 停车场 × 时段**」，不是单个值。列表按停车场分行，每行带四状态：

| 状态 | 含义 |
|---|---|
| 正常 | 当前在有效期内 |
| N 天后过期 | 临近到期（阈值由停车场「有效期到期提醒(天)」决定） |
| 已过期 | 区间已过 |
| **未生效** | 充了未来时段，尚未开始 |

## 三、显示屏三分类（v2.5 归一后）

| 官方叫法 | 装在哪 | 显示什么 | 典型型号 |
|---|---|---|---|
| **入口显示屏** | 出入口车道 | 过车信息（车牌/入场时间/金额/余额…） | — |
| **入口引导屏** | 入口 | 整场余位 | DS-TVB200 |
| **停车诱导屏** | 场内（室内+室外） | 分方向余位 | DS-TVL121/221/222/223 |
| （车位屏） | 单个车位上方 | 该位空/占红绿指示 | — |

⚠ 历史命名：原「入口诱导屏」→ 现「入口引导屏」；原「室内诱导屏」+「室外诱导屏」→ 合并为「停车诱导屏」。**看老稿子时注意换算。**

## 四、设备角色对照

| 官方叫法 | 俗称 | 在链路里是 |
|---|---|---|
| 抓拍单元 / ANPR | 抓拍机、车牌识别相机 | 眼睛（认牌） |
| 出入口控制设备 | 道闸、卡箱、票箱 | 手（抬杆） |
| 刷卡对讲设备 | 对讲柱 | 认卡认人 / 呼叫 |
| **道闸控制单元** | — | **角色不是设备**：车道上被指定负责抬杆的那一个 |
| 诱导管理器 | TPM 主机 | 诱导系统的大脑 |
| 自助查询设备 | 寻车终端 | 车主自助反查车位 |

⚠ **「道闸控制单元」是一个角色，不是一类设备。** 抓拍机/出入口控制设备/刷卡对讲都可担任；由谁担任决定了这条车道能不能配离线放行。

## 五、收费侧对照

| 维度 | 取值 |
|---|---|
| **收费来源**（谁收的） | 岗亭、中心收费、缴费机、车主账户扣费 |
| **收费方式**（用什么付） | 现金、POS、车主账户余额 |
| **收费类型**（按什么算） | 不收费 / 按次 / 按单位时长 / 分时段 / 分时 / 日夜分时按次 / 按单位时段 |
| **包期类型** | 包年(默认365天) / 包月(默认30天) / 自定义天数 / 闲时包月 |
| **减免方式** | 折扣 / 金额减免 / 全免 / 停车时长减免 |

⚠ 别把**收费来源**和**收费方式**混为一谈：缴费机是"来源"，现金是"方式"，一笔钱两者都有。

## 六、车位状态（五种）

空闲 / 占用 / 停车超时 / 非法停车 / 未知

⚠ 「未知」不是一种业务状态，是**没有相机或相机离线**导致的数据缺失。
⚠ 超时与非法并存时，按**非法停车**展示。

## 七、其他易混词

| 词 A | 词 B | 区别 |
|---|---|---|
| 车辆名单 | 名单下发 | 前者是平台内的车辆分组；后者是把名录推到前端设备 |
| 离线放行 | 黑白名单报警 | 同一个"名单下发"动作，前者下发到车道开闸，后者下发到相机只报警 |
| 关联抓拍机 | 关联监控点 | 前者参与识别与放行判断；后者只提供视频画面辅助查看 |
| 快速放行 | 登记放行 | 前者直接抬杆；后者需记备注/占用名单车位，用于异常留痕 |
| 中心收费 | 岗亭收费 | 前者先付后出；后者出场当场结算 |
| 续费 | 批量充值 | 前者在原基础上追加；**后者覆盖式，原有效期失效** |
| 余位统计 | 车位预留 | v3.1 起「余位统计」改名为「车位预留」 |
| IC 卡 | UHF 卡 | 近距刷卡 / 远距离识别，全链路带「远距离识别」标签 |
