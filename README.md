# HCP 停车场管理 · 业务知识库 2.0

> 这是 `hcp-parking-kb`（1.0）按新结构重整的版本，**内容同源，组织方式不同**。两者并列存在，1.0 未改动。

## 这是什么

HikCentral Professional「停车场管理」的业务知识库。**核心资产是一套可持续维护的知识**；讲解 HTML 等都是按需生成的临时快照。

## 三条轴（2.0 的核心）

一份知识按三种方式被找到：

| 轴 | 文件 | 回答 |
|---|---|---|
| **概念** | `业务认知/` | 这是什么、为什么这么设计、怎么跑 |
| **时间** | `版本迭代/` | 哪个版本改了什么；**这个功能怎么变成今天这样** |
| **空间** | `页面地图.md` | 这个页面最新稿在哪、是不是完整的 |

## 两种角色（先确认你是哪种）

| | **维护者** | **使用者** |
|---|---|---|
| 是谁 | 本业务线的设计负责人（1 人） | 新人 / 其他设计师 / 跨组 / 产品研发 |
| 手上有 | 完整工作台，**含 `原始素材/` 全部画板** | `git clone` 拿到的**纯文本知识**（约 190K，秒拉，不含素材） |
| 能做 | 归档、更新知识、推送版本 | 读、问、生成自己要的产出 |

> **边界：只有维护者改 `业务认知/`、`设计视角/`、`版本迭代/`。**
> 使用者只读；发现知识与实际不符 → **反馈给维护者**（或提 MR），不要自己改。

### 关于设计稿

`原始素材/`（设计画板、实况截图、白皮书）**不入 git**，使用者 clone 不到。

知识库里所有 `素材：xxx.png` 都是**检索线索，不是附件**。找稿子的实际流程是：

```
页面地图.md  →  拿到「完整基线在哪版 + 之后有哪些散落的迭代」
             →  带着 版本 + 素材文件名 + 需求号
             →  自己去设计软件里检索
```

所以知识库的职责到"**告诉你该找哪几张、它们各是整页还是局部**"为止，图本身由你在设计软件里取。

## 我该从哪进

| **设计师找稿子** | `页面地图.md` |

```
│   ├── 术语与实体.md    跨主题实体、关系、官方命名对照
│   └── <6 个业务主题>.md  含「边界与异常」一节
│
├── 设计视角/            横切：设计侧知识
│   ├── 角色与旅程.md
│   ├── 设计范式.md      ★ 出新稿前先看有没有现成解法
│   └── 体验缺口.md      观点层，与事实层隔离
│
├── 版本迭代/            时间切
│   ├── README.md        版本时间线（表格，每版一行）
│   ├── 演进脉络.md      ★ 六条跨版本主线，手写不可生成
│   └── v2.5 … v3.2.md   逐版明细（含 页面 / 范围 / 需求号）

├── 原始素材/            不入 git：画板 / 实况截图 / 白皮书
├── 产出/                不入 git：按需快照，用完可弃
└── _临时/               不入 git：切片等中间产物
```

## 相对 1.0 改了什么

| 1.0 | 2.0 | 为什么 |
|---|---|---|
| `设计源/` | `原始素材/` | 里面早就不只是设计物（含白皮书、实况截图） |
| `变更记录.md` 单文件 | `版本迭代/` 按版本切分 | 单文件会无限膨胀，读一次烧掉全部版本 |
| —— | `版本迭代/演进脉络.md` | 第三条轴。"有效期怎么变成今天这样"两条轴都答不了 |
| —— | `页面地图.md` | 设计师按**页面**找东西，不按业务主题 |
| —— | 变更条目加 `范围`（整页/区块/单控件） | **"最新稿"≠"完整稿"**，局部优化稿只画了一个下拉框 |
| 「模块」一词 | 拆为**业务主题** + **页面** | 研发指功能闭环、设计师指三级页面，歧义 |
| 术语散落 | `业务认知/术语与实体.md` | AI 写文案对齐命名，需求不绑定任何单一主题 |
| 边界异常散落 | 下沉到各主题的「边界与异常」节 | 边界天然跟着主题走，不该全库通读 |
| 索引手写 | 由 front-matter 生成 | 手写索引必然与实际脱节 |
| 存疑写在 00_总览 | `待确认.md` + 三档证据等级 | 防止推测混进事实 |
